# 外部环境统一访问规范

版本：2026-11-15-v1。NAS 维护源：`/mnt/hdd/script_tools/connkit/docs/agent-access-policy.md`。本机副本为受管理的同步文件，不按 CLI 的长期记忆分别维护连接参数。

1. 所有受管理外部环境的日常访问，统一通过名为 `connkit` 的 MCP。包括远程服务器、RDP、NAS 远程管理、数据库、缓存、对象存储、Kubernetes 和内部管理 API。
2. 每次开展环境工作，先调用 `connections_list`，按当前任务选择并核对 connection_id、名称、类型和授权范围。连接是否存在、凭据、代理路线、证书/主机密钥及授权，以 ConnKit 当前登记状态为准；历史记录只作定位线索。
3. 使用登记连接对应的工具进行检查和操作，例如 connection_test、rdp_*、db_*、ssh_exec、sftp_*、redis_*、k8s_*、https_request。具体工具名和参数先查实时 tools/list，不凭记忆猜接口。
4. 不从旧笔记、长期记忆、临时凭据文件或其他 CLI 配置提取目标凭据来绕过 ConnKit；不得因为 MCP 没加载、连接失败或缺少工具而自动改走 ssh/scp、直连 RDP、数据库客户端、kubectl、curl 或自建代理。
5. 未登记、权限不足、代理/证书错误、工具不支持时，明确说明缺口，按本次用户授权补齐 ConnKit 的连接或能力。没有相应授权就停在缺口处，不默默降级直连。不能把“未登记”说成“目标环境不存在”。
6. 用户可以明确授权某次直连例外。记录目标、目的和有效范围，仅完成该次任务；该例外不成为其他 CLI 或后续任务的默认。连接器自身的引导、修复也需要明确授权，不能把它用作长期绕过路径。
7. connection_test 成功要区分 TCP、协议协商、证书校验、身份认证和业务操作。列到工具、读到配置或端口可达都不等于真实业务验收通过。
8. MCP 提供连接能力，不扩大任务授权。连接列表有写/执行能力不代表可以任意停服、改库、修改权限或删除数据；仍按当前用户任务和目标范围执行。
9. 本地文件、构建和本机进程继续用本机工具。CLI 在 NAS 上运行时，NAS 上的本地文件操作仍是本地操作；不能把远程访问伪装成本地任务来绕过本规范。公开文档检索、普通网页查询、既有模型服务和正常 Git 工作流不属于这里的远程环境管理。
10. 新增 CLI/运行环境时，先配置 ConnKit MCP、加载本规范、验证 initialize/tools/list/connections_list，再做目标连接验证。未通过时明确标注，不能仅复制配置就宣布接入完成。

入口由各 CLI 的 MCP 配置提供。当前受信任局域网入口是 `http://192.168.31.51:8082/mcp`，沿用服务器已有匿名连接授权与网络策略；不修改服务端访问策略，不创建额外权限或凭据。
